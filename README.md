# dsh-bagu

给一段话，数三样东西，再问你几个问题。

数的是：

1. **具体物** —— 每百字有几个数字、时间点、第一人称经历、原话、专有名字。
   这些东西只有真的在场的人才给得出。
2. **撑场面的话** —— 意义、价值、本质、趋势这类抽象词，「重要、关键、深刻」这类评价词。
   说得越多，越是在说事之外加光。
3. **留白词** —— 好像、应该、大概、可能。一个都没有，说明全篇没有一处不确定。

另算一个结构腔密度：不是X而是Y、先…再…、三段并列、破折号、「首先其次综上」，
跟同一文体的真人基线比，超三倍就报。

输出长这样：

```text
[判断] 换谁都行 · 把这些句子搬到另一个人嘴里，读起来不会有差别。
[具体] 每百字 0 个具体物 · 抽象词 1 · 评价词 1
[留白] 0 个（0/千字） —— 一个都没有，等于句句在下断言
[结构腔] 49.2/千字 · 基线的 37.8 倍
```

底下跟一组问句，比如「开头就在总结，删掉这一句，下面的东西还站得住吗」。
**它不给答案，也不改你的字。**

## 它解决不了什么

先说清楚，免得期待错位。

**它不管「整段话是不是人写的」，只管这段话里有没有可以指认的痕迹。**
通篇一个调子、每段都收个小结论、同一件事换个说法又说一遍 —— 这些它看不见。

**它是体温计，不是退烧药。** 测出来 49/千字不会让你的话变好。真要让一段话立起来的是
真实经验、只有当事人知道的细节、真的想说的观点。这三样插件给不了，模型也自己长不出来。

**它假设用的人愿意照镜子。** 会被说「一股 AI 味」的，多半是直接把输出复制出去。
这类人不会半夜开个 Node 脚本对着七个问句逐条想。对这种情况，工具的效果约等于零。

**规则会过期。** 今天有效的识别特征，一旦被规则化，就变成可学习、可识别的模式，
接着被新写法绕过。这是个止血带。

## 它跟别的工具不一样在哪

市面上的同类多是**改写器**：读进去，吐一版「更像人」的。这类工具的问题是把话改了，
事也跟着丢了，而且改出来的东西有它自己的均匀。

这个只读不写。给坐标，不给成品。

## 三个指标为什么这么定

- **具体物**：可替换的反面。谁都能说的话里，一定没有只有当事人知道的东西。
- **留白**：真人在不确定时会松口，AI 倾向给结论。一个「大概」都没有的段落，是在下断言。
- **结构腔**：这些句式人类也用，只是密度极低。问题不是用不用，是用得多不多。
  而且同一种句式重复两次不算病 —— 真人会重复自己的习惯，AI 是轮着用工具箱。
  所以看的是同一百字里**几种不同句式扎堆**。

## 装了以后

系统提示里多一节「说话的念头」（讲念头，不列禁用词），两个只读工具：

```js
bagu_check({ text: "……" })   // 指标 + 判档 + 问句
bagu_ask({ text: "……" })     // 只要问句
```

## 装

```sh
git clone https://github.com/hongdougao111/dsh-bagu.git
dsh plugin --profile web add link:/path/to/dsh-bagu
```

或者直接用 release 里的 `dsh-bagu-0.1.0.tgz`。装完重启一次 dsh
（宿主半侧和系统提示那一节都是启动时装配的）。

手动改 profile 的 `cordis.patch.yml` 也行：

```yaml
- insert:
    - id: bagu
      name: dsh-bagu
      config:
        enabled: true
        prompt: true
        order: 921
```

## 测试

```sh
npm test    # 13 个
```

## 边界

- 中文为主，英文没专门校过
- 基线取自中文评论语料，写长文和文档时会偏严 —— 那类文体本来就该有结构
- 不给总分。分数会让人只盯数字，不看句子
